## Executive Summary

An exhaustive technical investigation into the backend server (`api/main.py`), SQLite storage (`data/platform.db`), and oceanographic virtual sensors (`virtual_sensors/`) was conducted to resolve telemetry flatlining on the AQUILA OS frontend.

### Primary Root Causes Identified:
1. **Absence of a Continuous Telemetry Daemon in the Backend Lifecycle:** When the FastAPI server runs (`uvicorn api.main:app`), it does not initiate any background task or thread to update telemetry. The server is strictly reactive, reading whatever is currently in `data/platform.db`.
2. **Database Frozen in Past State (Flatline Cause):** The database table `sensor_readings` contains 127,973 rows, but the newest timestamp is `1788301406.872161` (Sep 1, 2026). Because no new rows are written, `/api/telemetry` repeatedly returns the exact same snapshot (`TEMP=8.005°C`, `PSAL=35.004 PSU`, `DOXY=None`, etc.), causing the React frontend charts (`OceanState.tsx`, `MissionControl.tsx`) to render completely flat lines.
3. **Module Shadowing Import Crash in Standalone Simulators:** `telemetry_simulator.py`, `digital_twin_engine.py`, and `test_backend_api.py` all fail immediately on startup with `ModuleNotFoundError: No module named 'platform.database'; 'platform' is not a package` because they attempt to import from `platform.database`, which conflicts with Python's standard library `platform` module. The local package was renamed to `platform_pkg/`, but the scripts were never updated.
4. **Virtual Sensors Module Disconnected from SQLite/FastAPI:** `virtual_sensors/virtual_publisher.py` was originally authored for an external Mosquitto MQTT broker setup (`localhost:1883`) that omitted `TEMP` and `PSAL`, while the FastAPI server queries SQLite directly.
5. **NetCDF Temperature Profile Calibration:** The dummy NetCDF file `data/argo_southern_ocean.nc` (generated by `create_dummy_nc.py`) was synthesized with warm equatorial temperatures (~20°C to 25°C) instead of the Southern Ocean Indian Sector water column temperature range mandated by R1 (**1.5°C to 2.5°C**).

## 1. Virtual Sensors Architecture & Analysis

The `virtual_sensors/` directory provides physically realistic virtual oceanographic sensors based on BGC-Argo profiles and published sensor accuracy specifications.

### 1.1 `virtual_sensors/noise_engine.py`

#### Structure and Specs:
- **`SensorSpec` Dataclass:**
  - `noise_std: float` — Gaussian measurement noise standard deviation (matches published sensor physical accuracy).
  - `ar1_rho: float` — Autoregressive AR(1) temporal autocorrelation coefficient ($0 = \text{white noise}, 1 = \text{random walk}$).
  - `drift_rate: float` — Linear drift accumulation rate per reading (biofouling / electrode degradation).
  - `dropout_prob: float` — Probability of transient single-reading packet loss per tick.
  - `outage_start_prob: float` — Probability of an extended sensor outage event starting.
  - `outage_mean_duration: int` — Mean duration of outages in reading counts (geometric distribution).

- **Sensor Calibration Constants (`SENSOR_SPECS`):**
  Based on the Argo User Manual (v3.41) and SOCCOM BGC-Argo quality control documentation:
  | Parameter | noise_std | ar1_rho | drift_rate | dropout_prob | outage_start_prob | outage_mean_dur |
  | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
  | **TEMP** | 0.002 °C | 0.70 | 0.00005 | 0.005 | 0.002 | 5 |
  | **PSAL** | 0.010 PSU | 0.70 | 0.00010 | 0.005 | 0.002 | 5 |
  | **DOXY** | 2.000 $\mu\text{mol/kg}$ | 0.80 | 0.02000 | 0.010 | 0.005 | 8 |
  | **CHLA** | 0.020 $\text{mg/m}^3$ | 0.60 | 0.00050 | 0.020 | 0.008 | 10 |
  | **PH_IN_SITU_TOTAL** | 0.005 pH | 0.75 | 0.00010 | 0.010 | 0.003 | 6 |
  | **NITRATE** | 0.500 $\mu\text{mol/kg}$ | 0.80 | 0.01000 | 0.010 | 0.004 | 7 |

- **`VirtualSensor` Class:**
  - `__init__(parameter: str)`: Validates parameter against `SENSOR_SPECS`, initializes AR(1) state `self.prev_ar1 = 0.0`, accumulator `self.drift_accumulator = 0.0`, `reading_count = 0`, `outage_remaining = 0`.
  - `read(true_value: float) -> tuple[Optional[float], Optional[float], str]`:
    - Simulates extended outages (`status = "OUTAGE"`, returns `None, None, "OUTAGE"`).
    - Simulates single packet dropouts (`status = "DROPOUT"`, returns `None, None, "DROPOUT"`).
    - Adds Gaussian electronic noise: $\epsilon \sim \mathcal{N}(0, \sigma_{\text{noise}})$.
    - Adds AR(1) temporal correlated noise: $\xi_t = \rho \xi_{t-1} + \mathcal{N}(0, 0.3 \sigma_{\text{noise}})$.
    - Accumulates sensor drift: $\Delta_{\text{drift}} += r_{\text{drift}} \times \mathcal{N}(1.0, 0.2)$.
    - Computes: $\text{measured} = \text{true\_value} + \epsilon + \xi_t + \Delta_{\text{drift}}$.
    - Calculates 2-sigma sensor uncertainty: $2.0 \times \sigma_{\text{noise}}$.
    - Returns `(round(measured, 4), round(uncertainty, 4), "ONLINE")`.
  - `reset_drift()`: Clears accumulated drift and AR(1) memory during maintenance recalibration.

### 1.2 `virtual_sensors/profile_interpolator.py`

- **`ProfileInterpolator` Class:**
  - `PARAMETERS = ["TEMP", "PSAL", "DOXY", "CHLA", "PH_IN_SITU_TOTAL", "NITRATE"]`
  - `__init__(dataset_path: str = "data/argo_southern_ocean.nc")`: Loads NetCDF dataset with `xarray.open_dataset()`.
  - `select_nearest_profile(lat: float, lon: float) -> int`: Computes Euclidean distance across `profile_lats` and `profile_lons` to find index of closest real Argo profile.
  - `get_value_at_depth(profile_idx: int, depth_m: float, parameter: str) -> Optional[float]`:
    - Extracts `PRES` and requested `parameter` arrays.
    - Filters NaNs (`valid = ~(np.isnan(pressures) | np.isnan(values))`).
    - Requires $\ge 4$ valid data points.
    - Fits cubic spline (`scipy.interpolate.interp1d(kind="cubic", fill_value=(values[0], values[-1]))`).
    - Returns interpolated parameter at `depth_m`.
  - `get_full_profile(profile_idx: int, parameter: str) -> dict`: Returns depth list, values list, units, and float WMO identifier for vertical profile UI plots.

### 1.3 Other Files in `virtual_sensors/`

- **`dl_sensor_replicator.py` (`ArgoDerivedSensorModel`):**
  A two-stage ML model: (1) Cubic interpolation; (2) `GradientBoostingRegressor` trained on `PRES`, `TEMP`, and `PSAL` to cross-predict dissolved oxygen (`DOXY`) when direct observations are missing.
- **`virtual_publisher.py`:**
  A standalone MQTT publisher script. Note: It connects to MQTT on port 1883, only publishes DOXY, CHLA, PH, and NITRATE (missing TEMP and PSAL), and does not write to SQLite.
- **`validator.py`:**
  Evaluates cubic interpolation accuracy against withheld Argo test profiles (80/20 split), reporting MAE, RMSE, and $R^2$.
- **`verify_aaiw.py` & `verify_doxy.py`:**
  Oceanographic verification scripts confirming the Antarctic Intermediate Water (AAIW) salinity minimum signature (at 800–1100 dbar) in the NetCDF dataset.

## 2. Database Architecture & Schema (`data/platform.db`)

### 2.1 Schema Definition (`platform_pkg/database.py`)

The platform uses SQLite with WAL (Write-Ahead Logging) mode and foreign keys enabled:
- Connection helper: `platform_pkg.database.get_connection() -> sqlite3.Connection`
  - `PRAGMA journal_mode=WAL`
  - `PRAGMA foreign_keys=ON`
  - `row_factory = sqlite3.Row`
- Database location: `data/platform.db`

#### Tables:
1. **`sensor_readings`:**
   ```sql
   CREATE TABLE sensor_readings (
       id          INTEGER PRIMARY KEY AUTOINCREMENT,
       sensor      TEXT    NOT NULL,
       value       REAL,
       unit        TEXT,
       source      TEXT,
       uncertainty REAL,
       depth_m     REAL,
       status      TEXT    DEFAULT 'ONLINE',
       qc_flag     INTEGER DEFAULT 1,
       platform    TEXT    DEFAULT '001',
       timestamp   REAL    NOT NULL,
       synced      INTEGER DEFAULT 0
   );
   CREATE INDEX IF NOT EXISTS idx_sensor_readings_sensor
       ON sensor_readings (sensor, timestamp DESC);
   ```
2. **`detections`:**
   Stores side-scan sonar object detections with bounding boxes (`bbox_x`, `bbox_y`, `bbox_w`, `bbox_h`), calibrated confidence, class labels, and geo-coordinates (`lat`, `lon`, `depth_m`).
3. **`mission_log`:**
   Logs vehicle mission state transitions (`phase`, `depth_m`, `lat`, `lon`, `timestamp`).

#### Step 3: Implement In-Process Background Telemetry Daemon in `api/main.py`
Rather than relying on an external manual process, embed a daemon thread or `asyncio.create_task` inside `api/main.py` on startup:
```python
import asyncio
from virtual_sensors.noise_engine import VirtualSensor
from virtual_sensors.profile_interpolator import ProfileInterpolator
from platform_pkg.mission_fsm import MissionFSM
from platform_pkg.database import get_connection

async def continuous_telemetry_worker():
    """Continuously advances AUV physics and persists virtual sensor readings to SQLite."""
    interpolator = ProfileInterpolator(str(ROOT / "data" / "argo_southern_ocean.nc"))
    profile_idx = interpolator.select_nearest_profile(-54.2, 60.8)
    sensors = {
        param: VirtualSensor(param) 
        for param in ["TEMP", "PSAL", "DOXY", "CHLA", "PH_IN_SITU_TOTAL", "NITRATE"]
    }
    mission = MissionFSM()
    battery = 100.0
    lat, lon = -54.201, 60.810

    while True:
        try:
            mission.step()
            depth = mission.current_depth()
            phase = mission.current_phase()
            battery = max(15.0, battery - 0.005)
            now = time.time()

            readings = [
                ("depth", depth, "m"),
                ("battery", battery, "%"),
                ("lat", lat, "deg"),
                ("lon", lon, "deg"),
                ("mission_state", phase, ""),
                ("phase", phase, ""),
                ("uptime", int(now - START_TIME), "s"),
            ]

            # Sample virtual sensors with physical noise engine
            for param, sensor_obj in sensors.items():
                true_val = interpolator.get_value_at_depth(profile_idx, depth, param)
                if true_val is not None:
                    measured, unc, status = sensor_obj.read(true_val)
                    if measured is not None:
                        unit = interpolator._get_units(param)
                        readings.append((param, measured, unit))

            # Batch write to SQLite in WAL mode
            conn = get_connection()
            try:
                with conn:
                    for s_name, s_val, s_unit in readings:
                        conn.execute("""
                            INSERT INTO sensor_readings
                            (sensor, value, unit, source, uncertainty, depth_m, status, qc_flag, platform, timestamp, synced)
                            VALUES (?, ?, ?, 'VIRTUAL_BGC_ARGO', 0.0, ?, 'ONLINE', 1, '001', ?, 0)
                        """, (s_name, s_val, s_unit, depth, now))
            finally:
                conn.close()

        except Exception as exc:
            log.warning("Telemetry loop iteration error: %s", exc)

        await asyncio.sleep(1.5)  # 1.5-second cadence matches frontend polling
```
